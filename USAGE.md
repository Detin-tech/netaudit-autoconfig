# NetAudit AutoConfig Usage Guide

## Overview

NetAudit AutoConfig is a Python + Ansible-based utility that scans networks, inventories devices and services, identifies misconfigurations, and optionally applies auto-remediation playbooks.

## Quick Start

### Installation

1. Clone the repository:
   ```
   git clone https://github.com/yourusername/netaudit-autoconfig.git
   cd netaudit-autoconfig
   ```

2. Create a virtual environment and activate it:
   ```
   python3 -m venv netaudit-env
   source netaudit-env/bin/activate
   ```

3. Install dependencies:
   ```
   pip install -r requirements.txt
   ```

4. Install Nmap (required for network scanning):
   ```
   # Ubuntu/Debian
   sudo apt-get install nmap
   
   # CentOS/RHEL
   sudo yum install nmap
   
   # macOS
   brew install nmap
   ```

### Basic Network Scan

To scan a network subnet and generate a report:

```bash
python3 netaudit.py --subnet 192.168.1.0/24 --output network_scan.md
```

### Detailed Audit with Configuration Check

To perform a detailed audit against baseline configurations:

```bash
python3 netaudit.py --subnet 192.168.1.0/24 --audit --config-path ./config/baseline_configs/ --output detailed_audit.md
```

### Auto-Remediation Mode

To automatically apply fixes for identified issues:

```bash
python3 netaudit.py --subnet 192.168.1.0/24 --audit --auto-fix --config-path ./config/baseline_configs/ --playbook-path ./playbooks/ --output remediation_report.md
```

## Command-Line Options

| Option | Description | Required |
|--------|-------------|----------|
| `--subnet` | Subnet to scan in CIDR notation | Yes |
| `--audit` | Perform configuration audit | No |
| `--auto-fix` | Apply automatic remediation | No |
| `--config-path` | Path to baseline configuration files | No (defaults to ./config/baseline_configs/) |
| `--playbook-path` | Path to Ansible playbooks for remediation | Yes if using --auto-fix |
| `--output` | Output report file path | No (defaults to report.md) |

## Understanding the Results

### Report Structure

Reports generated by NetAudit AutoConfig include:

1. **Host Inventory**: List of discovered hosts with open ports and services
2. **Security Findings**: Identified issues grouped by risk level:
   - Critical: Immediate attention required
   - High: Should be addressed soon
   - Medium: Recommended to address
   - Low: Informational
3. **Summary**: Overall statistics of the scan

### Risk Levels Explained

- **Critical**: Issues that pose immediate security risks (e.g., RDP exposed to the internet)
- **High**: Issues that should be addressed quickly (e.g., SSH accessible with weak authentication)
- **Medium**: Issues that are recommended to fix for better security posture
- **Low**: Informational findings or minor improvements

## Extending NetAudit AutoConfig

### Adding Custom Rules

Custom audit rules can be added as YAML files in the `config/rules/` directory. See `config/rules/cis_ubuntu_2204.yaml` for an example.

### Creating New Playbooks

New Ansible playbooks for remediation should be placed in the `playbooks/` directory. Follow the naming convention `harden_<service>.yml` for consistency.

### Modifying Baseline Configurations

Baseline configurations are stored in `config/baseline_configs/`. These define the "secure" state that the auditor checks against.

## Troubleshooting

### Common Issues

1. **Nmap not found**: Ensure Nmap is installed on your system
2. **Ansible not found**: Verify Ansible is installed in your virtual environment
3. **Permission denied**: Some operations require sudo privileges

### Getting Help

For additional help, use:

```bash
python3 netaudit.py --help
```

## Example Use Cases

### Internal Network Audit

System administrators can use NetAudit AutoConfig to regularly scan internal networks for misconfigurations:

```bash
python3 netaudit.py --subnet 10.0.0.0/24 --audit --output internal_network_audit.md
```

### Compliance Checking

Organizations can check compliance with security standards by using appropriate rule sets:

```bash
python3 netaudit.py --subnet 192.168.0.0/24 --audit --config-path ./config/rules/cis_ubuntu_2204.yaml --output cis_compliance_report.md
```

### Automated Patching

DevOps teams can integrate NetAudit AutoConfig into their CI/CD pipelines for automated security patching:

```bash
python3 netaudit.py --subnet 172.16.0.0/24 --audit --auto-fix --playbook-path ./playbooks/ --output patching_report.md
```
